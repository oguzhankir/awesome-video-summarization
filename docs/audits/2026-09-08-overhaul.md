### Official GitHub HTML check

The foundations chapter was sent to GitHub's official Markdown endpoint before and after the repair. Initial HTML contained 70 math wrappers but six unwrapped display delimiters: three equations had become accidental headings because their equals/minus operators occupied separate lines. The same response stripped some norm, set-brace and spacing escapes. A local KaTeX pass alone had not detected either Markdown-stage defect.

Following [GitHub's documented math syntax](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions), 105 display expressions now use fenced `math` blocks and 233 inline expressions use backtick protection. Rechecking the same foundations document produced **73 math wrappers, one Mermaid wrapper and zero unwrapped display delimiters**. Spot inspection confirmed preserved norm, brace and spacing escapes. Regression checks cover unsafe operator-only lines in dollar-delimited blocks and enforce the macro policy inside fenced mathematics.

The requested expansion of this API check to every document was rejected by automatic approval review as broader external data transfer. It was not performed. Every document passed local parsing; only the foundations chapter has the recorded official HTML check. GitHub's browser subsequently runs math and Mermaid rendering, so HTML wrapper success does not certify browser layout or client rendering.
